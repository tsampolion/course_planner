# 4.1.0 Audit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the owner's 4.1.0 audit as five pull requests (A, D, B, C, E, built in that order), each its own release.

**Architecture:** Plain-Kotlin models and helpers carry every rule so they are unit-tested on the JVM; Compose files only render them. Pacing stays untouched: new per-group book data enters through the single seam `Plan.forGroup` (`engine/GroupOverrides.kt`). Book type is new model data (JSON schema 15, read leniently).

**Tech Stack:** Kotlin, Jetpack Compose (Material 3), `org.json`, JUnit. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-24-audit-4-1-0-design.md`

## Global Constraints

- Every PR: set `versionName` in `app/build.gradle.kts`, `versionCode` +1 (currently 49), add a `## [X] - date` CHANGELOG section with compare link, update stale docs (CLAUDE.md, README features, docs index). PR versions: A `0.4.1.1`, D `0.4.2.0`, B `0.4.3.0`, C `0.4.4.0`, E `0.4.4.1`.
- Before each commit: `./gradlew testDebugUnitTest`; before each push also `./gradlew lint assembleRelease`. CI also runs these.
- Engine parity is the contract: with no overrides, no removed books and Unclassified books, schedules are identical (existing `PacerTest`, `GroupOverridesTest`, `AssignmentTest` stay green untouched).
- Visible text goes in `res/values/strings.xml` (`NoHardcodedTextTest`). Colours only from `ui/theme/Tokens.kt`, spacing only `Space.*`, menus via `PacerDropdownMenu`, icons only from `AppIcons.kt`.
- No new copy beyond strings the features need; no wording changes elsewhere until the owner returns the string inventory.
- Do not change `applicationId`, the signing setup, the `INTERNET`-only permission, or the asset name pattern `course-pacer-<version>.apk`.
- Compose-only, no new dependencies. Weekdays 0 = Sunday in JSON. Edits go through `edit`/`editYear`/`editClass`/`editGroup`; structural edits take no tag.
- Develop on branch `claude/dreamy-gauss-o0a26w` for PR A; later PRs restart the same branch name from the latest `main` after the previous PR merges (per session instructions). Open each PR ready for review and subscribe to its activity.
- Visual changes cannot be run on a device here; each PR description says "needs a phone check" and lists what to look at.

## Review Focus

- A version string with 3 parts (old) or 4 parts (new) arriving from storage or GitHub must never crash and never be offered when not newer.
- A class where every book has the same type (e.g. three Readers) must still produce distinct abbreviations (R1, R2, R3).
- Removing the last remaining core book from a group must be refused, not leave an unpaceable group.
- A group finish date for a book later than the group/year end must not extend the term.
- Hero Done/edit on a test day, blocked lesson, or no-lesson state must not crash or mark a wrong lesson.
- Large text and tablet widths must still reach Settings from group home (pills reflow, none clipped).
